# Token 消耗与 MiMo 算力规划

## 当前试点消耗

| 指标 | 当前口径 |
| --- | --- |
| 团队规模 | 约 60 人全栈研发团队 |
| 日均 AI 调用 | 约 3200 万 Token |
| 月度基础消耗 | 约 9.6 亿 Token |
| 个人搭建与调优消耗 | 累计超过 1.2 亿 Token |
| 原生缓存命中率 | 约 14% |
| 分层缓存命中率 | 约 78% |
| 无效 Token 损耗 | 降低 60% 以上 |

## 消耗来源

| 场景 | Token 消耗特征 | 说明 |
| --- | --- | --- |
| 代码生成 | 高频、中等上下文 | 覆盖日常功能开发、样板代码和局部实现 |
| 代码重构 | 中高频、长上下文 | 需要读取多文件上下文、规范约束和历史变更 |
| 单测生成 | 高频、结构化输出 | 适合批量自动化，但重复请求较多 |
| 代码评审 | 高频、相似语义多 | 是语义缓存收益最大的场景之一 |
| 文档生成 | 低中频、长上下文 | 适合长上下文模型和结果缓存 |
| 闭环验证 | 中频、多轮迭代 | 失败日志分析和修复建议会产生多轮调用 |

## MiMo 算力价值

MiMo 在本体系中适合作为团队级基础算力层，承担高频、日常、可规模化的研发任务：

- 日常研发问答和上下文解释。
- 单测生成、PR 描述和评审摘要。
- 规范解释、修复建议和失败日志归因。
- 多 Agent 闭环中的中间推理、格式化输出和低成本重试。
- 与 CC Switch 缓存层配合，复用相似任务结果，降低重复消耗。

## 后续扩容需求

全面投产后，预计新增以下场景：

- 前端工程化：组件规范检查、样式一致性、可访问性提示、交互状态补齐。
- 自动化测试：单测、集成测试、端到端测试生成和失败归因。
- 长文本知识库解析：研发规范、事故复盘、接口文档、技术债记录的长期沉淀。
- 多模态业务分析：截图、日志、报表、用户反馈和产品需求的综合分析。
- 多 Agent 深度联动：更长链路、更大上下文、更复杂的自动化验证闭环。

## 目标消耗规划

| 阶段 | 范围 | 月度 Token 预估 | 目标 |
| --- | --- | --- | --- |
| 试点期 | 核心研发链路打通 | 约 9.6 亿 | 验证可用性、缓存收益和评审覆盖 |
| 扩容期 | 全团队正式投产 | 约 12 亿到 14 亿 | 提升稳定性、降低人工评审负担 |
| 深化期 | 新场景全面接入 | 约 16 亿 | 支撑多 Agent 长链推理和复杂业务分析 |

## 申请诉求

百亿 Token 额度将主要用于：

1. 支撑 60 人研发团队从试点走向正式投产。
2. 承载多 Agent 长链推理中的高频调用和多轮迭代。
3. 为 MiMo 在代码生成、单测生成、评审摘要和验证归因场景建立稳定评测样本。
4. 继续优化 CC Switch 分层缓存、跨模型路由和团队级 Token 治理能力。
5. 输出可复用的开源文档、配置模板和实践报告，帮助更多团队低成本接入 MiMo。

# 小米 MiMo 百亿 Token 计划申请摘要

## 项目名称

基于 Codex + CC Switch 的多模型 AI 驱动研发全流程 Agent 体系

## 一句话介绍

本项目以 Codex 桌面端作为研发交互入口，以 CC Switch 作为统一多模型网关、缓存管控和 Token 治理核心，构建覆盖代码生成、重构、测试、文档、评审和 CI/CD 验证的多 Agent 协同研发体系。

## 申请背景

研发团队在规模化使用 AI 开发工具时，面临模型能力不均衡、模型切换成本高、重复语义请求造成 Token 浪费、代码规范依赖人工审核、技术债难以持续治理等问题。单一模型无法覆盖代码重构、单测生成、长文档解析、日常问答和安全评审等差异化场景，因此需要统一模型调度、跨模型缓存和团队级用量治理能力。

## 项目方案

本项目通过 CC Switch 统一接入 MiMo、DeepSeek、通义千问、Kimi 等模型，根据任务类型进行动态调度。系统拆分为五类 Agent：

1. 代码监听 Agent：扫描 Git 仓库，完成 AST 解析和上下文预处理。
2. 规范匹配 Agent：加载架构规范和安全规则，生成重构需求清单。
3. 多模型调度 Agent：通过 CC Switch 路由不同模型，统一进行 Token 统计、语义缓存和请求节流。
4. 代码重构 Agent：执行自动化重构、单测生成、文档更新和 PR 生成。
5. 闭环验证 Agent：触发 CI/CD、测试和安全扫描，不通过则回传迭代优化。

## 当前成果

试点阶段已在约 60 人全栈研发团队中打通主要研发链路，覆盖代码生成、重构、测试、文档和评审场景。当前日均 AI 调用约 3200 万 Token，月度基础消耗约 9.6 亿 Token。项目从零搭建、多模型适配、缓存架构调优和 Agent 长链逻辑调试过程中，个人累计自主消耗 Token 超过 1.2 亿。

通过 CC Switch 分层缓存方案，缓存命中率从约 14% 提升至约 78%，直接削减 60% 以上无效 Token 损耗。同时，代码评审覆盖率显著提升，人工重复审核压力下降，线上隐性问题减少，验证了该架构在研发团队中的实用价值。

## MiMo 使用规划

MiMo 将作为团队级高频研发任务的基础算力层，重点承担：

- 日常研发交互与代码解释。
- 单测生成和失败日志归因。
- PR 摘要、评审摘要和规范解释。
- 多 Agent 流程中的低成本中间推理。
- 与 CC Switch 缓存层结合，提升跨任务复用率。

后续正式投产后，系统将扩展到前端工程化、自动化测试、长文本知识库解析、多模态业务分析等场景，预计月度整体 Token 消耗提升至约 16 亿。百亿 Token 额度将用于保障项目持续迭代、稳定评测 MiMo 在研发场景中的表现，并沉淀可复用的开源模板和实践报告。

## 预期产出

- 一套基于 CC Switch 的多模型研发 Agent 调度实践。
- MiMo 在代码生成、单测、评审、文档和验证归因场景下的使用报告。
- 面向团队级 AI 研发的 Token 治理、缓存复用和成本优化方案。
- 可公开复用的文档、配置模板、Agent 骨架和路线图。

## 申请诉求

希望获得小米 MiMo 百亿 Token 计划支持，用于支撑本项目从试点走向全团队正式投产，完成多 Agent 长链推理、跨模型缓存、团队级 Token 治理和研发质量闭环的持续扩容。

# 五类专项 Agent 设计

## 1. 代码监听 Agent

职责：

- 监听 Git 仓库变更、分支差异和 PR 变更。
- 对代码进行 AST 解析、依赖关系提取和上下文摘要。
- 标记高风险文件、重复代码、复杂函数、缺失测试和历史缺陷热点。

输入：

- Git diff、目标分支、仓库语言栈、目录规则。
- 历史提交、历史 review 记录和线上问题标签。

输出：

- 结构化代码上下文。
- 技术债候选清单。
- 需要进入规范匹配的文件和函数范围。

## 2. 规范匹配 Agent

职责：

- 加载公司架构规范、编码规范、安全规则、接口契约和测试要求。
- 对代码监听 Agent 的结果进行语义匹配。
- 生成不合规项、风险等级、推荐修复方式和验收标准。

输入：

- 代码上下文。
- 架构规范、安全规则、历史缺陷规则。

输出：

- 重构需求清单。
- 安全风险说明。
- 单测与验证建议。

## 3. 多模型调度 Agent

职责：

- 通过 CC Switch 统一接入 MiMo、DeepSeek、通义千问、Kimi 等模型。
- 按任务类型、上下文长度、成本预算、缓存命中和失败率选择模型。
- 管控 Token 消耗、请求路由、限流、降级和跨模型缓存复用。

推荐调度策略：

| 任务 | 首选模型 | 备用模型 | 调度理由 |
| --- | --- | --- | --- |
| 日常研发问答 | MiMo | DeepSeek | 高频、低延迟、低成本 |
| 单测生成 | MiMo | 通义千问 | 结构化输出稳定，适合批量生成 |
| 代码重构 | DeepSeek | 通义千问 / MiMo | 代码理解和约束推理优先 |
| 长文档生成 | Kimi | MiMo | 长上下文整理优先 |
| 规范解释 | MiMo | Kimi | 高频可缓存，解释稳定 |
| PR 描述 | MiMo | Kimi | 摘要、变更说明和风险提示 |

输出：

- 模型选择结果。
- Token 预算和实际消耗。
- 缓存命中记录。
- 降级与重试记录。

## 4. 代码重构 Agent

职责：

- 根据重构需求清单生成最小可审查 Patch。
- 补充单元测试、集成测试或快照测试。
- 更新必要文档、迁移说明和 PR 描述。
- 把变更拆成可验证、可回滚的提交单元。

输入：

- 规范匹配结果。
- 代码上下文。
- 模型调度结果。

输出：

- Patch 或 PR。
- 测试文件。
- 文档更新。
- 风险说明和回滚建议。

## 5. 闭环验证 Agent

职责：

- 自动触发测试、lint、安全扫描和 CI/CD。
- 汇总失败日志，定位失败类型和责任模块。
- 将失败原因回传给多模型调度 Agent，进入下一轮修复。
- 验证通过后生成合入建议。

输入：

- PR、Patch、测试结果、CI 日志、安全扫描报告。

输出：

- 验证报告。
- 可合入判断。
- 失败迭代任务。
- 质量指标沉淀。

## Agent 闭环标准

每一轮 Agent 协同至少保留以下信息：

- 任务来源和业务目标。
- 涉及文件和影响范围。
- 使用模型和路由原因。
- Token 消耗和缓存命中情况。
- 生成变更和测试结果。
- 残留风险和下一轮动作。

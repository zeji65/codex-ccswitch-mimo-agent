# 迭代路线图

## Phase 1：申请展示骨架

目标：

- 完成项目 README、架构、Agent 流程、Token 规划和申请摘要。
- 建立 GitHub 可展示的文档入口。
- 明确后续开源模块边界，避免泄露企业私有规则和代码。

交付：

- 申请材料文档包。
- Agent 工作流说明。
- Token 消耗规划。
- 后续开源路线。

## Phase 2：配置模板开源

目标：

- 抽象 CC Switch 多模型路由配置。
- 提供 MiMo、DeepSeek、通义千问、Kimi 等模型的调度示例。
- 提供缓存策略和 Token 统计字段模板。

交付：

- 示例路由配置。
- Agent 任务配置模板。
- 缓存命中统计样例。
- 本地演示脚本。

## Phase 3：Agent 骨架实现

目标：

- 提供五类 Agent 的最小可运行骨架。
- 支持读取 Git diff、生成任务清单、调用模型、输出报告。
- 保持企业私有规则可插拔。

交付：

- 代码监听 Agent 最小实现。
- 规范匹配 Agent 规则接口。
- 多模型调度 Agent 配置适配。
- 重构和验证 Agent 的命令行骨架。

## Phase 4：闭环验证增强

目标：

- 接入测试、lint、安全扫描和 CI 日志解析。
- 增强失败归因和自动重试策略。
- 输出团队级质量报表。

交付：

- 验证报告模板。
- CI 失败归因器。
- 质量指标面板草案。
- PR 自动摘要和风险说明。

## Phase 5：规模化落地报告

目标：

- 汇总 MiMo 在研发场景中的实际调用数据。
- 对比缓存命中、成本下降、评审覆盖和线上问题变化。
- 形成可公开分享的实践报告。

交付：

- 月度 Token 使用报告。
- 缓存收益报告。
- 研发效率提升报告。
- MiMo 场景适配建议。

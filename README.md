# 基于 Codex + CC Switch 的多模型 AI 驱动研发全流程 Agent 体系

## 项目定位

本项目面向研发团队规模化使用 AI 开发工具的核心场景，以 Codex 桌面端作为研发交互入口，以 CC Switch 作为统一多模型网关、模型切换入口、语义缓存与 Token 管控层，构建一套覆盖代码生成、重构、测试、文档、评审与验证的多 Agent 协同体系。

当前仓库用于沉淀可公开展示的架构说明、工作流设计、Token 规划和后续开源骨架。企业内试点中的业务规则、私有代码库、内部规范与安全配置会逐步抽象为可复用的开源模块、配置模板和最佳实践。

## 核心痛点

1. 研发团队 AI 开发需求覆盖代码生成、重构、测试、文档和审查等全场景，单一大模型难以稳定适配多元任务，多模型手动切换带来高额适配成本，缺乏统一调度和管控入口。
2. 同类语义请求高频重复，原生缓存命中率不足，重复上下文和重复评审消耗大量 Token，月度调用成本难以精细化控制。
3. 存量代码技术债积压，代码规范落地依赖人工审核。日常提交频繁时，人工评审容易出现覆盖不足、风格不一致、隐性缺陷沉淀和研发工时被重复性审核挤占的问题。

## 解决方案

系统以 CC Switch 为多模型接入和治理核心，把不同模型的能力封装为可调度资源，通过五类专项 Agent 组成长链推理流程：

1. 代码监听 Agent：扫描 Git 仓库，解析代码结构，提取上下文和技术债特征。
2. 规范匹配 Agent：加载公司架构规范、安全规则和工程约束，定位不合规项并生成重构需求清单。
3. 多模型调度 Agent：通过 CC Switch 统一路由，按任务类型选择模型，并进行 Token 预算、语义缓存和请求节流。
4. 代码重构 Agent：执行自动化重构、单测生成、文档更新和 PR 生成。
5. 闭环验证 Agent：触发测试、安全扫描和 CI/CD 验证，失败后回传问题并进入下一轮优化。

## 多模型分工

| 任务类型 | 推荐模型 | 主要原因 |
| --- | --- | --- |
| 日常交互、单测补全、轻量代码任务 | MiMo | 响应稳定、适合高频研发协作，适合作为团队级基础算力 |
| 代码重构、复杂代码理解 | DeepSeek / 通义千问 | 适合代码结构分析、批量重构和工程约束推理 |
| 长文档生成、知识库解析 | Kimi | 适合长上下文材料整理、规范文档和研发知识沉淀 |
| 调度与治理 | CC Switch | 统一模型入口、路由策略、缓存命中、Token 统计和权限治理 |

## 试点成果

基于当前试点口径，体系已完成研发链路打通和企业级试用：

- 团队规模：约 60 人全栈研发团队。
- 覆盖范围：代码生成、重构、测试、文档、评审、验证闭环。
- 日均 AI 调用：约 3200 万 Token。
- 月度基础消耗：约 9.6 亿 Token。
- 个人搭建与调优消耗：累计超过 1.2 亿 Token。
- 缓存命中率：从约 14% 提升到约 78%。
- 成本优化：直接削减 60% 以上无效 Token 损耗。
- 工程收益：代码评审覆盖率提升，重复人工审核减少，线上隐性问题下降。
